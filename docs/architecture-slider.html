02B · Write transformation

写入：消息如何变成长期证据

每次转换都补充结构与身份：原始调用先成为可追踪消息，压缩产生工作记忆，显式记忆或闭合 slot 再生成稳定 L2 evidence，最后以同一 mem_id 投递固化任务。

02C · Read transformation

读取：查询如何变成可注入上下文

查询先被规范化为有界检索计划，再并行生成情景、事实和图谱候选；只有 L2 情景候选参与 dense/sparse 融合与 F2 重排，最后与 L3/L4 结果组装。

02D · Consolidation transformation

固化：证据如何变成版本化事实与图谱

当前实现由确定性规则抽取事实候选，F5 负责所有同 key 异值的仲裁；高价值证据再派生图谱节点。LLM Gateway 尚未接入此主链路。

02E · Field lineage example

一条偏好如何贯穿写入、固化与召回

以“请记住 user.lang_pref=zh”为例，追踪同一语义在各层中的形态变化。字段会逐步结构化，但 scope、来源证据和事实键始终可反向定位。

08
01 · USER

原始请求

session_id: "session-a"role: "user"content: "请记住 user.lang_pref=zh"scope_id: human_mem_project
NORMALIZE保留原文，补齐内部项目 scope，并识别显式记忆意图。
02 · L0

Message

turn_id: 12 · token_len: nrole: user · ts: nowsource_id:scope/.../session-a/turn/12
PROMOTE显式路径跳过等待；F1 计算 importance，正文规范化后生成稳定 mem_id。
03 · L2 + INBOX

Evidence

CONSOLIDATEInbox 以 mem_id 找回完整 L2；规则解析 key=value，并保留 evidence_ids。
04 · L3

SemanticFact

fact_key: user.lang_prefvalue: zh · partition: preferenceversion: 1 · confidence: cevidence_ids: [mem_id]
INDEX写入版本链与 preference 分区；evidence_hash 固定本次证据集合。
05 · RECALL

RecallResult

query: "回复语言是什么？"facts[0].fact_key: user.lang_preffacts[0].value: zhepisodes[] · reinforced[]
DELIVERpreference 分区优先进入 facts；上层 Agent 据此选择中文回复。
身份连续scope_id 从入口贯穿 Message、EpisodicMemory、InboxItem、SemanticFact。
证据连续Message.source_id → L2.source_ids；L2.mem_id → L3.evidence_ids。
语义连续原文可重放，结构化事实可检索，召回结果仍携带版本与证据。
字段不是被覆盖，而是在可追溯标识上逐层增加语义

02F · Graph projection

图谱：高价值证据如何变成节点与边

L4 不是另一份事实主存，而是从 L2 派生的关系视图。当前实现创建 insight 与 entity 节点，并以 belong 边连接；节点按类型和规范化 label 幂等合并。

09
01 · GATE

EpisodicMemory

mem_id · text · mem_typeimportance · access_countsource_ids[] · status=activescope_id
ELIGIBILITYimportance ≥ 6 或 access_count > 1 才进入图谱投影，否则只保留 L2/L3。
02 · DERIVE

Graph Inputs

label = insight_labeler(text)entities = extract_entities(text)[:5]evidence_ids = [mem_id]type = semantic | procedural
SCOREinsight salience = min(1, .3 + importance/10)；实体显著度取其 80% 且不低于 .3。
03 · INSIGHT

GraphNode

node_type: insightnode_id: uuid5(scope + type + label)label · salience · status=activeevidence_ids: [mem_id]
UPSERT相同规范化 label 复用 node_id，合并 evidence_ids，并保留更高 salience。
04 · RELATE

Entity + Edge

entity.node_type: entityentity.label · evidence_idsedge: insight → entityedge_type: belong · weight: .7
CONNECT实体同样按 label 幂等 upsert；重复边更新权重，不复制关系。
05 · READ MODEL

Subgraph

nodes[]: id/type/label/salienceedges[]: source/target/type/weight按 query label 或 entities 选种子按 salience 截断到 k
RETURN作为 RecallResult.subgraph 返回；图查询失败时降级为空图，不阻断事实和 episode。
来源约束insight 必须引用 L2 mem_id，不能成为无证据的权威事实。
失效约束证据被替换或归档时，相关 insight 标记为 superseded。
重建约束L4 是派生读模型，可由 L2/L3 与 outbox 重放恢复。
Evidence 生成 Insight，Insight 连接 Entity，Subgraph 服务上下文扩展

02G · Forget transformation

遗忘：低价值证据如何安全退出

遗忘不是直接删除一条记录，而是先计算保持率和综合分数，再改变 L2 状态，并将失效证据级联到 L3 置信度和 L4 图谱审计。

10
01 · SNAPSHOT

Active Memory

status · ts_last_accessstability · importanceaccess_count · occupancygrace protection
TO F3跳过 deleted；新 active 记录在 grace window 内受保护。
02 · RETENTION

F3 Score

elapsed = now - last_accessretention = exp(-elapsed/stability)范围: 0..1时间越久，保持率越低
TO F4将时间衰减与重要性、访问频次组合，避免只按时间粗暴删除。
03 · DECISION

F4 + θdyn

importance_factor=.5+.5*i/10access_factor=ln(1+count)+1F4=F3 × importance × accessθdyn = f(store occupancy)
TRANSITIONactive 且 importance<9、F4<θ → archived；archived 且 F4<.1θ → deleted。
04 · CASCADE

Affected Evidence

archived_ids[] + deleted_ids[]L3 only-evidence fact: confidence - penalty低于 threshold: remove fact keyL4 salience decay + isolated prune
TO AUDIT失效证据不直接改写历史内容，而是驱动事实降权、节点剪枝和孤儿边检查。
05 · RESULT

Forget Report

checked · archived · deletedtheta_dyn · occupancyl3_degraded · l3_removedl4_pruned · graph_audit
PERSISTscope 标记 dirty，并返回 storage_path；后续快照保存治理后的完整状态。
可逆阶段archived 仍可参与 recall，并在命中 reinforce 后恢复 active、增加 stability。
保护阶段importance ≥ 9 的 active 记忆不会被常规 decay sweep 自动归档。
一致性阶段删除证据后同步审计 L3/L4，避免事实和图谱继续引用失效来源。
先归档、再删除、后级联；召回强化可以延长高价值记忆寿命

02H · Conflict transformation

冲突：候选事实如何变成版本与审计

F5 在写入前同时读取候选和当前权威版本。相同值合并证据，不同值先分类、定级再裁决；任何异值路径都会生成 ConflictRecord。

11
01 · CANDIDATE

Incoming Fact

fact_key · value · confidencescope_id · partition · mem_typeevidence_ids[] · ts_updateevidence_hash · embedding
VALIDATE低于 confidence threshold 直接 reject，并记录 source 类型拒绝日志。
02 · LOOKUP

Current Version

versions = facts[scope][fact_key]current = versions[-1]value · confidence · evidence_idsvalid_from · valid_until
COMPARE无当前版本则 created；同值不形成冲突，合并证据并取更高 confidence。
03 · DETECT

Conflict Shape

type: temporal | negation | valueseverity: high | mid | lowrivals: [current.to_dict()]evidence_check
CLASSIFY时序 key 优先标记 temporal；否定语义单独分类，其余异值为 value。
04 · RESOLVE

ConflictAction

temporal → archive双高 confidence → pending显著 confidence delta → replace/keep近似时按时间、证据数裁决
APPLYreplace/archive 追加 version；pending/reject/keep 保持当前权威值。
05 · OUTPUT

Version + Audit

SemanticFact.version = current + 1old.valid_until = incoming.ts?ConflictRecord: old/new/actionconflict_id · policy_hit · resolved_to
CASCADEreplace/archive 返回 superseded_evidence_ids，驱动相关 L4 insight 标记过期。
同值不是冲突合并 evidence_ids，confidence 取最大值，更新时间取较新值。
双高不静默覆盖current 与 incoming 均 ≥ .95 时进入 pending，保留人工或策略复核空间。
时序保留历史archive 关闭旧 valid_until，新事实追加为下一版本。
裁决结果与审计记录同时产生，事实变化始终可解释

02J · Production mapping

生产写穿：领域对象如何映射到外部存储

当前 Production Adapter 先执行内存实现，再把同一结果写入外部依赖。它验证了协议和字段映射，但读取仍以进程内状态为主，尚不具备多实例远程权威语义。

HybridSearchPipeline

SEARCH
1vector / keyword / graph routes

3score dimensions + reranker
4graph related expansion
